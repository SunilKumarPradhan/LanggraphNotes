# Building a Chatbot using LangGraph

## Overview

This lecture introduces building a conversational chatbot using LangGraph with memory capabilities. The tutorial demonstrates how to create a basic chatbot that can maintain conversation history across multiple interactions, progressing from a simple single-query system to a fully interactive chatbot with persistent memory using checkpointers and memory savers.

## Key Concepts

### **Chatbot Architecture**
A chatbot in LangGraph is essentially an LLM-based workflow consisting of:
- A **sequential workflow** with a single node
- User messages as input
- LLM-generated responses as output
- Continuous loop execution until user exits

### **State Management**
The **State** is the core data structure that stores all conversation information:
- Contains a `messages` attribute that holds all exchanged messages
- Messages are stored as a list of `BaseMessage` objects
- Includes both human messages and AI responses
- Maintains complete conversation history

### **Message Types**
LangGraph uses different message types inherited from `BaseMessage`:
- **HumanMessage**: Messages typed by users
- **AIMessage**: Responses generated by the LLM
- **SystemMessage**: Role specifications for the LLM
- **ToolMessage**: Messages related to tool usage

## Building the Basic Chatbot

### Step 1: Define the State

```python
from typing_extensions import TypedDict
from typing import Annotated
from langgraph.graph.message import add_messages
from langchain_core.messages import BaseMessage

class ChatState(TypedDict):
    messages: Annotated[list[BaseMessage], add_messages]
```

**Key Points:**
- `ChatState` inherits from `TypedDict`
- `messages` is an annotated list of `BaseMessage` objects
- **add_messages** is a reducer function that appends new messages instead of replacing them

### Step 2: Create the Chat Node

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI()

def chat_node(state: ChatState):
    messages = state["messages"]
    response = llm.invoke(messages)
    return {"messages": [response]}
```

**Functionality:**
- Extracts current messages from state
- Sends messages to the LLM
- Returns the AI response wrapped in a list

### Step 3: Build the Graph

```python
from langgraph.graph import StateGraph, START, END

graph = StateGraph(ChatState)
graph.add_node("chat_node", chat_node)
graph.add_edge(START, "chat_node")
graph.add_edge("chat_node", END)

chatbot = graph.compile()
```

**Workflow Structure:**
- START → chat_node → END
- Simple sequential flow with one node

### Step 4: Test the Chatbot

```python
from langchain_core.messages import HumanMessage

initial_state = {
    "messages": [HumanMessage(content="What is the capital of India?")]
}

result = chatbot.invoke(initial_state)
answer = result["messages"][-1].content
print(answer)  # Output: "The capital of India is New Delhi."
```

## Implementing Interactive Chat Loop

### Creating a Continuous Conversation

```python
while True:
    user_message = input("Type here: ")
    
    if user_message.strip().lower() in ["exit", "quit", "bye"]:
        break
    
    print(f"User: {user_message}")

```

**Features:**
- Continuous loop for ongoing conversation
- Exit conditions: "exit", "quit", or "bye"
- Displays both user and AI messages

## The Memory Problem

### Issue Identified
The basic chatbot **cannot remember previous conversations** because:
- Each `invoke()` call starts with a fresh state
- Previous conversation history is lost between invocations
- The chatbot treats each interaction as independent

### Example of the Problem

```
User: Hi, my name is Nitesh
AI: Hello Nitesh, how can I assist you?
User: What is my name?
AI: I'm sorry, but I don't have access to your personal information.
```

**Root Cause:**
- Multiple `invoke()` calls within the loop
- Each invocation creates a new state from scratch
- No persistence of conversation history across invocations

## Implementing Persistence

### **Persistence Concept**
**Persistence** allows the chatbot to retain state information across multiple workflow executions by:
- Storing state in memory (RAM) or database
- Retrieving previous state before processing new messages
- Maintaining conversation continuity

### Adding Memory with Checkpointers

```python
from langgraph.checkpoint.memory import MemorySaver

# Create a checkpointer
checkpointer = MemorySaver()

# Compile graph with checkpointer
chatbot = graph.compile(checkpointer=checkpointer)
```

### Defining Threads

**Thread**: Represents one user's interaction session with the chatbot

```python
thread = {"configurable": {"thread_id": "1"}}
```

**Purpose:**
- Identifies different user sessions
- Allows multiple users to interact simultaneously
- Each thread maintains its own conversation history

### Updated Invocation with Config

```python
while True:
    user_message = input("Type here: ")
    
    if user_message.strip().lower() in ["exit", "quit", "bye"]:
        break
    
    print(f"User: {user_message}")
    
    config = {"configurable": {"thread_id": "1"}}
    
    response = chatbot.invoke({
        "messages": [HumanMessage(content=user_message)]
    }, config=config)
    
    ai_message = response["messages"][-1].content
    print(f"AI: {ai_message}")
```

### How Persistence Works

1. **First Interaction:**
   - User sends: "Hi, my name is Nitesh"
   - State stores both user message and AI response
   - Workflow ends, state saved to RAM

2. **Second Interaction:**
   - User sends: "What is my name?"
   - LangGraph retrieves previous state from RAM
   - Appends new message to existing conversation history
   - LLM receives complete context
   - AI correctly responds: "Your name is Nitesh"

3. **Subsequent Interactions:**
   - Each new message is appended to growing conversation history
   - Complete context maintained throughout session

## Important Distinctions

### RAM vs Database Storage

| Feature | RAM (MemorySaver) | Database |
|---------|-------------------|----------|
| **Persistence** | Only while program runs | Permanent storage |
| **Use Case** | Development/Testing | Production systems |
| **Data Retention** | Lost on program restart | Survives restarts |
| **Best For** | Simple chatbots | Multi-session applications |

### Reducer Functions

**Why use `add_messages` instead of `operator.add`?**
- `add_messages` is optimized for `BaseMessage` objects
- Recommended by LangGraph for message handling
- Provides better performance and compatibility

## Summary

### Key Takeaways

- **Chatbots in LangGraph** are sequential workflows with state management
- **State** stores conversation history using a list of messages
- **Reducer functions** like `add_messages` append rather than replace messages
- **Basic chatbots** lose memory between invocations without persistence
- **Persistence** enables conversation continuity across multiple interactions
- **Checkpointers** store state in memory or databases
- **Threads** identify individual user sessions
- **MemorySaver** provides RAM-based persistence for development
- **Production systems** should use database-backed persistence
